# 셀 애니메이션풍 코드 단편: 연출·제작 스킬

80~90년대 극장판·OVA 셀 애니메이션처럼 보이는 단편을 코드로 만들 때 쓴다. 대본·컷 리스트는 screenplay-writing / content-plan 스킬로 먼저 만든다. 이 스킬은 작품을 만들 때마다 새로 검증된 노하우를 5·6장에 누적해 갱신한다. 참고 구현: GitHub mini-ok/ssoksok-channel-assets 의 `scarecrow/` (cel.py, painter.py, bg.py, film.py, audio.py, knowhow.md).

## 0. 대원칙

1. **최종 프레임은 손으로 그린 셀과 포스터컬러 배경처럼 보여야 한다.** 3D·절차적 기법은 레이아웃·원근·조명 계산에만 쓴다.
2. **캐릭터 감정 통로는 2~3개.** 얼굴 표정·대사로 설명하지 않는다. 캐릭터 규칙(예: 바람이 불 때만 움직인다)을 두면 규칙을 깨는 순간이 클라이맥스가 된다. 규칙 안에서도 우연(바람·낙엽)을 이용해 감정을 읽히게 할 수 있다(바람이 모자 챙을 내리고 단풍잎이 볼에 붙어 '민망함').
3. **규칙을 깨는 순간은 '세상이 멈춘 시간'으로 연출한다.** 바람·소리·눈발(입자 시간 고정)을 모두 멈추고 그 정적 속에서만 움직이게 하면 설명 없이 읽힌다. 움직임은 단계(키 포즈 + 홀드)로, 단계마다 짧은 소리 하나.
4. **크기가 대비되는 짝**을 둔다. 작은 쪽이 관객 대신 반응한다.
5. **빛의 흐름이 감정의 흐름.** 조명 아크를 브리프에 먼저 적는다. 같은 장소를 계절·시간대별로 다시 칠하면 일관성과 다채로움을 동시에 얻는다.
6. **샘플 → 컨펌 → 전체 진행.** 모델 시트와 대표 프레임 4장, 그리고 짧은 움직임 시험 영상을 먼저 확인받는다. 본 제작에 들어가도 애니마틱(7장 4단계)을 건너뛰지 않는다.
7. **검수는 실제 크기 정지 프레임 + 원본 크기 크롭 전후 비교.** 개선은 항상 같은 장면의 이전/이후 크롭으로 확인한다. 컷 묶음마다 대표 프레임 시트를 만들어 문제를 찾고 고친 뒤 다음 묶음으로. 연기·타이밍은 정지 프레임으로 통과시키지 않고 저해상도 움직임 영상으로 확인한다.
8. **이야기와 기법의 적합성을 기획 첫 단계에서 검사한다.** 감정이 실루엣·캐릭터 규칙·환경(빛·바람·물)으로 읽히는 이야기를 고른다. 손과 물건의 접촉(끈 매기, 물 퍼 담기, 손잡기), 복잡한 생활 동작, 미묘한 표정이 핵심인 사람 연기는 코드 인형으로 무너진다 — 그런 이야기는 피하거나, 2D 캐릭터 하이브리드·인형/가면처럼 뻣뻣함이 설정인 디자인·원경과 실루엣 연출로 바꾼다.
9. **분량: 2~3분에 10~14컷, 장소 1~2곳, 사건 3개 이하.** 영웅 숏 4~6개에 시간 대부분을 쓴다. 컷당 5초 안팎으로 30컷을 넘기면 장면이 숏 하나로 끝나 감정이 쌓이지 않는다. 시나리오 분량은 코드 제작 단가(컷마다 연기를 수작업 키잉)를 기준으로 설계한다.

## 1. 아트 디렉션 브리프 템플릿 (`brief.md`)

1. 목표 한 문장: 시대·매체·촬영 방식 + "3D·모션그래픽·움직이는 일러스트 아님"
2. 결과물 형식 (MP4 / 단독 HTML 플레이어)
3. 스타일: 특정 작품이 아닌 시대의 전통을 재료 어휘로 (포스터컬러 붓자국, 평면 셀 + 그림자 1~2톤, 따뜻한 선, 그레인, 게이트 흔들림, 헐레이션, 들뜬 검정)
4. 등장 존재 제한
5. 장면 비트: 행동은 횟수와 점층으로
6. 캐릭터 디자인: 실루엣, 재질, 포인트 색, 글자·로고 없음, 감정 통로, 캐릭터 규칙, 모델 유지
7. 선: 연필·잉크 손선 굵기 변화, 컬러 홀드 라인(그림자 쪽 차가운 색, 빛 쪽 따뜻한 색)
8. 채색: 평면 + 그림자 1~2톤, 팔레트 5~7색, 그라디언트는 하늘·안개·빛에만
9. 배경: 포스터컬러, 종이 질감, 반복 금지, 정점에 하모니 프레임
10. 조명 아크
11. 이펙트: 그린 조각을 2프레임마다 갱신, 파티클 느낌 금지
12. 애니메이션: 투스·스리스, 키 포즈와 긴 홀드, 겹침 동작, 큰 존재 느리게/작은 존재 빠르게
13. 연출: 컷 순서와 감정 곡선
14. 금지 목록 (3장)
15. 감정 목표 한 문장
16. 자체 검수 지시
17. 이야기-기법 적합성 메모: 이야기가 요구하는 동작 목록과, 각 동작을 이 엔진으로 어떻게 처리할지(또는 화면 밖·생략·원경으로 돌릴지)

## 2. 작화·타이밍 구현 규칙

- **투스·스리스**: `floor(t*12)/12`, 큰 동작 `floor(t*8)/8`. 카메라도 기본 투스.
- **키 포즈와 홀드**: (시각, 포즈, 전환 길이) 목록, 전환에는 계단식 중간 그림 1~2장만. smoothstep 연속 보간 금지. 0→1 전환은 `step(u, a, b, n)`(n장 계단).
- **오버슛과 안착**: 큰 동작은 목표를 한 번 넘었다가(예: −0.45) 제자리(−0.2)로 돌아온다.
- **착지**: 찌그러짐 0.78 → 늘어남 1.12 → 1.0(각 2프레임), 착지 후 반응 포즈를 홀드.
- **빈 홀드**: 코미디의 타이밍은 아무 일도 일어나지 않는 0.6~1초에서 나온다.
- **라인 보일**: 형태 시드 고정, 미세 떨림 시드만 투스마다 교체(`set_frame(t)`).
- **변형 금지**: 포즈마다 형태를 다시 그린다(점 목록 재계산).
- **같은 모델 유지**: 캐릭터는 하나의 그리기 함수에서만 나온다. 부품 사이 끼워 그리기가 필요하면 훅(예: `chest_fn`)을 둔다. 작은 캐릭터는 큰 캐릭터가 돌려주는 기준점(모자 꼭대기, 소매 끝)에 붙인다. 떨어져 나가는 소품(모자)은 같은 그리기 코드를 단독 함수(`straw_hat`)로 빼서 캐릭터 안팎에서 공유한다.
- **캐릭터와 배경 카메라 분리**: 배경은 넓게(하늘이 보이도록), 캐릭터는 크게 — 로우앵글·클로즈업을 원근 계산 없이 만든다. **단, 배경에 그려진 지형(둔덕) 위에 캐릭터를 놓는 컷은 두 카메라를 같게** 해야 발이 땅에 붙는다.
- **카메라 기준점은 포즈의 실제 좌표로**: 캐릭터를 빈 캔버스에 한 번 그려(장치 좌표 = 세계 좌표) 눈·소매 끝·가슴 위치를 캐시해 두고 클로즈업 카메라 중심으로 쓴다(`jpts`). ECU는 배율 13 안팎(z 7.5는 CU).
- **배경 카메라가 세계 밖을 비추지 않는지** 확인: 화면 가장자리 = cx ± (W/2)/z 가 배경 폭 안이어야 검은 띠가 안 생긴다.
- **3D 카메라는 배우를 따라가는 조준점으로**(〈숨비〉 C30에서 검증): 카메라 위치와 시선 목표를 배우 좌표 + 오프셋 키로 주면, 배우 동선을 고쳐도 구도가 따라온다. 고정 좌표 카메라를 엿보기로 고쳐 맞추지 않는다.

## 3. 검수 체크리스트

- [ ] 3D 느낌 없음 (플라스틱, CG 셰이딩, 완벽한 원근)
- [ ] 게임 에셋 느낌 없음 (저폴리 면을 따라가는 선, 3단 툰 램프의 PS2 인상, 정점 격자 바다·평면 카드 구름)
- [ ] 벡터 느낌 없음 (완벽한 곡선, 균일한 외곽선, 평행이동한 그림자)
- [ ] 웹 애니 느낌 없음 (미끄러운 이징, 퍼펫 관절)
- [ ] AI 그림 느낌 없음 (디자인 변화, 녹은 디테일)
- [ ] 스타일 일치 (광택 셰이딩·서양 카툰·실사·인상파 유화 아님)
- [ ] 아마추어 느낌 없음 (빈 배경, 반복 요소, 탁한 색, 물방울무늬처럼 고르게 흩은 조각)
- [ ] 빛 과다 없음 (블룸·화이트아웃)
- [ ] 소리 없이도 캐릭터 감정이 읽힘
- [ ] 포즈가 의도와 다른 뜻으로 읽히지 않음 (기울기 합이 60°를 넘으면 '다이빙/댑')
- [ ] 얼굴이 측면에서 뒤통수처럼 읽히지 않음, 눈썹·속눈썹 선이 의도와 다른 감정(화남)으로 읽히지 않음
- [ ] 손에 든 물건·손잡기가 공중에 떠 보이지 않음
- [ ] 인물 비율이 서로 맞음(한 인물만 머리가 크거나 작지 않음)
- [ ] 소품·동물은 종의 특징이 실루엣에서 읽힘. 역광 하늘의 맹금류는 어둡게(실루엣)
- [ ] 사건 대상(매, 날아가는 모자)이 그 순간 실제로 화면 안에 있음
- [ ] 해·달이 구름에 가려지지 않음, 제목이 배경 요소(나무)와 겹치지 않고 읽힘
- [ ] 타이틀·크레딧이 본편과 같은 질감
- [ ] 배경에 속하는 큰 형태가 셀 층에 섞여 평평해 보이지 않음
- [ ] 컷 경계 앞뒤 프레임 확인, 원본 크기로 확인함, 움직임 영상으로 확인함

## 4. 엔진 선택

- **Python + cairo + numpy**: 검증됨(〈홀씨〉 회화 배경, 〈허수아비의 겨울〉 셀 캐릭터·포스터컬러 배경). 1080p 프레임당 약 1.2초, 2코어 청크 병렬로 125초 영상 약 16분. 평면적 공간감이 한계. 캐릭터 연기는 이쪽이 낫다.
- **three.js + 헤드리스 Chromium(SwiftShader)**: 검증됨(〈숨비〉 172초 33컷). three는 `npm i three@0.160.0` 후 상대 경로로 로드. color/id/normal/깊이/캐릭터 패스를 뽑아 Python으로 셀 마감(5장 '3D 셀 마감'). 배경·물속·카메라 이동에 강하다. 절차적 3D 인물(캡슐·선반 조립 + 관절 각도 키잉)은 인형처럼 보이고 사람 연기가 안 된다. CPU 2코어에서 3분 분량 전체 렌더 약 3시간 — 반복 수정 여유를 일정에 넣는다. 백그라운드 렌더는 큐 스크립트 + `.done` 표시 파일로 관리.
- **권장 하이브리드**: three.js 배경·카메라 + cairo 2D 캐릭터 합성. 사람이 연기해야 하는 작품은 이 방식을 먼저 검토한다.

## 5. 셀 질감 구현 (검증된 수치)

### 캐릭터 셀
- **손그림 실루엣**: 윤곽을 2.5px 간격으로 재샘플, 둘레를 따라 낮은 주파수(약 140px 주기) 흔들림 약 1px. 중간 주파수(25~40px)는 0.1px 이하 — 크게 하면 젤리처럼 울렁인다.
- **펜 압력 외곽선**: 빛 반대쪽 법선일수록 굵게(0.45→1.4배), 둘레 따라 ±18% 변화. 잉크는 윤곽 안쪽에 더 놓는다(바깥 35% / 안쪽 65%).
- **획 나누기**: 닫힌 윤곽을 둘레 길이에 따라 2~4획으로, 양끝 7% 테이퍼, 획끼리 살짝 겹침.
- **디자인된 그림자**: 그림자 폭을 둘레 따라 0.55~1.45배로 변화(형태 시드 고정).
- **촬영된 셀** (`cel_finish`): 0.5px 무름, 저주파 물감 얼룩 ±1.8%, 배경과 미세한 색 차(살짝 차갑게). 0.65px 이상은 흐릿해 보인다.
- **필름 후처리**: 헐레이션(밝기 0.72 이상 붉은 주황 번짐), 들뜬 검정 0.035, 게이트 흔들림 투스마다 ±0.6px.
- **동물 디자인**: 종 특징을 실루엣에(매: 손가락처럼 벌어진 첫째 날개깃 5개, 줄무늬 꼬리, 눈선, 갈고리 부리).
- **계절·조명 팔레트**: 캐릭터 팔레트를 계절별 곱셈·더하기·섞기(`tint_pal`)로 배경 빛에 맞춘다(노을: 주황 섞기, 달밤: 파랑 곱하기).

### 포스터컬러 배경 (painter.py)
- **방식**: 하늘·구름·땅을 한 장으로 합친 밑그림 → 구조 텐서 방향장(형태의 결) + 지역별 힌트(수평) → 반지름 26/13/6/3px 4단계 곡선 스트로크. 획은 밑그림 색과 0.16 이상 달라지면 멈춘다(경계 보존). 획마다 평평한 불투명 색 + 안쪽 붓결 줄 2~3개.
- **실패한 설정**: 화면 전체에 고른 잔붓 → 인상파 유화·모자이크.
- **성공한 설정**: 평평한 곳은 큰 붓·긴 획(하늘 길이 2.6배, 들판 2.0배), 잔붓은 오차가 큰 디테일 부위만(기준 0.06/0.09/0.13), 하늘 붓결 줄 약하게(0.18).
- **그린 디테일 되살리기**: 밑그림의 고주파(원본 − 2.2px 블러)를 0.7배 다시 더한다 → 물감 위에 선 디테일을 다시 그린 애니 배경 느낌.
- **하늘 소용돌이 방지**: 하늘에서는 방향장 가중치 0.25(수평 힌트 우선).
- **비용**: 2400×1300 한 장 약 35초 → 계절·장소별 PNG 디스크 캐시.
- **배경 패치워크**: 면(논배미 등)마다 색조를 다르게, 면 안 붓질은 형태의 방향을 따라, 경계(두렁) 폭을 변화시키고 풀 술을 상단에.
- **계절 세트**: 하늘 3~4스톱, 구름 사양(위치·폭·높이)과 들판 종류(벼/그루터기/눈/해빙/무논)를 계절별 dict로. 납작한 구름(높이 70 이하)은 벽돌처럼 보이므로 높이 100~130. 녹는 눈은 고른 타원이 아니라 두렁 아래 그늘에 띠로, 웅덩이는 불규칙 다각형 + 하늘 반사 한 줄. 모든 계절을 한 장 시트로 놓고 비교 검수.
- **둔덕을 언덕으로**: 채도 낮춘 녹색, 아래로 갈수록 어두운 띠 5단, 꼭대기 실루엣에 풀 술, 들꽃.
- **예외**: 시간에 따라 변해야 하는 지형(녹는 눈더미)은 캐릭터 층에 두고 질감 선(바람 물결)을 더한다 — 높이만 줄이면 '녹는' 애니메이션이 공짜로 생긴다.
- **하모니 프레임**: 완성 합성 프레임을 배경 해상도로 키워 painter(반지름 14/7/3.5/1.8, 디테일 0.55)로 다시 칠해 캐시, 카메라만 천천히 당긴다.
- **제목**: 밝은 하늘 위에는 어두운 잉크 글씨 + 밝은 테두리(Noto Serif CJK).

### 3D 셀 마감 (〈숨비〉 three/finish.py)
- **패스**: color(툰 램프), id(물체별 색), normal, 깊이, char(캐릭터만). 깊이는 선형(1 − 거리/DR)으로 저장해야 원경에서도 선 검출 문턱이 일정하다.
- **선**: id·normal·깊이 경계에서 잉크, 캐릭터 바깥 실루엣은 char 패스로 굵게. 선 진하기도 렌더 안개와 같은 식으로 흐리게 해야 원경 선이 떠 보이지 않는다.
- **알파 컷 카드**(고사리 등)는 패스별 재질에도 같은 알파 컷을 넣어야 id/깊이에 사각형이 찍히지 않는다.
- **실패한 것**: 저폴리 면을 normal 선이 그대로 따라가 각진 면이 드러남 + 3단 툰 램프 → 게임 에셋 느낌. 다음엔 형상을 세분화해 매끈하게 하거나 면 경계 선을 끄고, 바다·하늘은 정점 격자 대신 그린 텍스처나 2D 플레이트로.
- **잘 된 것**: 물속 — 커스틱 스포트라이트 + 볼륨 + 수면 창(불투명도 0.16 안팎) + 2프레임마다 갱신하는 셀 거품 스프라이트 줄기 + 열수구. 환경별 마감 프리셋(새벽 해안·낮·폭풍·숲·물속), 숲 근접 컷은 빛줄기 세기를 컷별로 낮춤.
- **입모양**: 음성 RMS를 12/s로 0/1/2 세 단계로 바꿔 데칼 입에 적용 — 정면 근접에서만 읽히고 측면·원경에서는 안 읽힌다.

### 사운드 (audio.py)
- 하나의 5음 음계 모티프를 계절마다 다른 화성으로(가을 장조 / 겨울 단조 / 봄 다른 조의 장조). 오카리나 = 사인 + 2·3배음 약간 + 숨소리 대역 잡음 + 지연 비브라토.
- 효과음은 컷 시각표에 맞춰 합성: 돌풍(대역 이동 잡음), 짚 바스락(크래클 알갱이), 참새(주파수 활), 매 울음(하강 + 떨림), 나무 갈라짐(고역 순간음 + 저역 신음 + 붐), 실 삐걱(가속하는 클릭). 숨비소리(해녀 휘파람 숨) = 고역 대역 잡음 + 하강 휘파람 사인.
- **정적 연출**: 정적 구간은 리버브 꼬리까지 0으로, 레벨러가 정적을 끌어올리지 않게 마스크, 정적 속 소리는 레벨링 후 고정 레벨로(주변 장면보다 RMS 약 10dB 낮게).
- 컷별 RMS를 표로 뽑아 확인(장면 사이 편차 ±4dB 안). 최종 믹스는 tanh 리미터.
- **대사(TTS)**: Gemini TTS(Cloud TTS v1 `text:synthesize`, 모델 `gemini-2.5-flash-tts`)가 한국어 감정 연기에 쓸 만하다. 서비스 계정 키는 대화에 붙이지 말고 환경 비밀값으로. 테이크는 수치(길이·음높이)로 고르지 말고 사용자에게 들려주고 고르게 한다.

## 6. 누적 노하우 (작품별)

- 〈빛지기〉: 블룸·화이트아웃 과다는 화면을 날린다. 사건이 너무 많으면 컷이 읽히지 않는다.
- 〈홀씨〉: 높이장 4톤 회화 볼륨은 배경에 강하다. 표정 통로 없는 주인공은 감정이 약하다. 전체 레벨러로 조용한 구간을 끌어올리면 들을 만하다.
- 〈허수아비의 겨울〉 (125초 22컷, 완성):
  - 벡터 느낌의 주범은 완벽한 곡선, 균일한 선 굵기, 평행이동 그림자. 배경의 일러스트 느낌은 포스터컬러 재채색 + 디테일 되살리기로 해결.
  - 동선이 물리(바람 방향)를 정한다: 작은 캐릭터가 왼쪽 소매로 가야 하므로 눈보라는 오른쪽→왼쪽, 눈더미는 바람그늘 쪽 긴 꼬리 + 기둥 쪽 가파른 면.
  - 포즈로 닿지 않는 거리는 포즈를 늘리지 말고 지형(눈더미)으로 해결.
  - 굽힘·머리·모자 기울기 합은 45° 안팎. 몸통 회전이 반대 팔을 들어 올리므로 그 팔을 내려 보정.
  - 쓰러진 캐릭터: 팔 길이를 줄이고 몸 아래 가장자리만 풀로 덮는다(얼굴까지 덮으면 지저분).
  - 남은 과제: 바깥 실루엣만 굵은 선, 평면적 공간감(three.js 결합).
- 〈숨비〉 (172초 33컷, three.js 3D 셀 + 대사 4줄, 1차 완성 — 이전 작품보다 스토리·비주얼 완성도가 낮다는 평가):
  - 주원인은 "코드" 자체가 아니라 이야기가 요구한 사람 연기(끈 매기, 물 퍼 담기, 안기, 손잡기, 표정)를 절차적 3D 인형이 감당 못 한 것. 〈허수아비〉는 "바람이 불 때만 움직인다"로 한계를 콘셉트로 바꿨지만, 〈숨비〉는 같은 한계 위에서 사실적인 연기를 요구했다(0장 8).
  - 〈빛지기〉의 사건 과밀이 반복됐다: 컷당 약 5초라 감정의 기둥(두려움의 이유, 결심, 재회)에 숨 쉴 틈이 없었고, 코미디 곁가지가 톤을 흩트렸다(0장 9).
  - 데칼 얼굴은 측면에서 뒤통수처럼 읽혔고(정면 3/4로 바꿔 해결), 눈썹이 머리카락에 가려 감정 통로가 눈·입뿐이었다.
  - 저폴리 면 + 3단 램프 + 격자 바다가 게임 에셋처럼 보였다. 3D 본편과 2D 회화 타이틀의 질감도 달랐다.
  - 애니마틱 없이 33컷을 바로 렌더로 갔고, 정지 프레임으로만 검수해 큰 수정 대신 땜질만 했다.
  - 대사는 부차적 원인 — 테이크를 사용자가 직접 듣고 고르게 하고, 측면·원경 대사 컷은 피한다.
  - 잘 된 것(재사용): 물속 환경, 배우 조준점 카메라, 선형 깊이 + 안개 연동 선, 숨비소리 합성, Gemini TTS 스크립트.

## 7. 진행 순서

1. 대본·컷 리스트 확정 + 이야기-기법 적합성 검사·분량 검사(0장 8·9)
2. 브리프 작성 → 확인
3. 모델 시트(기본·감정 포즈·소품) → 확인
4. 애니마틱(회색 상자 + 카메라 + 타이밍 + 임시음, 저해상도 영상) → 확인
5. 대표 프레임 4장 → 확인
6. 배경을 포스터컬러로 재채색(캐시) + 짧은 움직임 시험 영상(타이밍·라인 보일) → 확인
7. 필요한 계절 배경 전부 그려 한 장 시트로 검수(실패 패턴 고친 뒤 다시 칠함)
8. 컷 묶음(4~6컷)별 제작, 묶음마다 대표 프레임 시트 + 저해상도 움직임 영상 → 문제 수정 → 다음 묶음
9. 사운드(컷 시각표 고정) — 전체 렌더와 병렬로. 대사 테이크는 사용자가 듣고 확정
10. 전체 렌더 → 컷 경계 앞뒤 프레임·컷 시트 검수 → 음악 합치기 → 전달
11. GitHub에 작품 폴더(소스·음악 MP3·컷 시트·README·knowhow) 보관, 영상은 용량 때문에 제외
12. 작품에서 얻은 노하우를 5·6장에 추가해 스킬 갱신
