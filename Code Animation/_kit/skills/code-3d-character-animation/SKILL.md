# 코드 3D 캐릭터 애니메이션: 애니매틱 → Blender 최종 렌더

모델링 툴 없이 **코드만으로** 3D 캐릭터 단편을 만든다. three.js로 실시간 애니매틱을 만들어 작품 가능성을 먼저 판단하고, 그다음 같은 장면을 Blender(Cycles)로 옮겨 최종 렌더한다.
참고 구현: GitHub `mini-ok/ssoksok-channel-assets` → `Code Animation/char3d/`(〈심장의 휴가〉, 2분 15초). Blender 쪽 상세는 `char3d/blender/README.md`.
대본·컷 리스트는 대본 스킬로 먼저 만든다. 이 스킬은 작품을 만들 때마다 새로 검증된 것을 8장에 누적한다.

## 0. 대원칙
1. **물리 법칙 위배 금지(사용자 절대 규칙).** 캐릭터 몸 부위끼리, 캐릭터와 소품·벽, 캐릭터끼리, 바닥 아래로 통과·관통이 없어야 한다. 모든 프레임에 BVH 충돌 검사를 돌리고, 검사기가 잡는 관통 0건이 될 때까지 경로·자세를 고친다(눈으로만 보지 않는다).
2. **몸 연기로 말한다.** 감정 통로가 불빛 한 점이나 지도 점이면 복잡한 감정을 못 싣는다(〈지도〉 실패). 자세·타이밍·시선·표정이 있는 캐릭터로 간다. 표정은 큰 눈·눈꺼풀·눈썹·입 정도의 단순한 얼굴로.
3. **한 화면 언어.** 3D와 지도처럼 두 화면 언어를 번갈아 쓰면 관객이 매번 해독해야 해서 지루하다.
4. **애니매틱 먼저, 최종 렌더는 나중에.** 실시간 렌더로 전체를 먼저 보고 이야기·연기를 확정한 뒤 최종 렌더 방식을 정한다.
5. **다른 도구로 넘길 때: 차이 점검 → 보완안 의논 → 보완해서 내보내기(사용자 규칙).** 빠지거나 멈추는 요소를 자동으로 전부 찾고, 차이마다 보완 방법을 사용자와 정한 뒤 내보낸다. 차이를 남긴 채 렌더 대기열에 넣지 않는다.

## 1. 작업 순서(사용자 지시)
1. 시간이 드는 렌더 전에 **정지 샘플 → 짧은 움직임 → 컨펌 → 전체 렌더**. 새 기법·새 연출은 반드시 작은 샘플로 먼저.
2. 샘플은 **실제 전달 크기**로 직접 열어 확인하고 보낸다. 애니매틱과 같은 프레임을 나란히 놓은 비교 시트가 가장 잘 통했다.
3. 해석이 두 갈래인 선택(색 변환 AgX 대 Neutral, 안개 세기)은 나란히 보여 주고 고르게 한다. 그 밖의 세부는 Claude가 정한다.
4. 길이를 채우려고 같은 장면을 반복하지 않는다.
5. 공개 저장소에 사용자 고유의 시나리오 작법 용어를 쓰지 않는다. 작법이 담긴 기획 문서는 claude.ai 프로젝트 문서에만 둔다.
6. 커밋·푸시는 요청이 있을 때만, 작업 브랜치에서. main 병합은 사용자 확인 후.

## 2. 캐릭터 만들기
- **2D 디자인 → 3D 몸:** 2D 실루엣 경로를 부풀려(inflate) 매끈한 몸 메시를 만든다(`inflate.py`, 3D 1단위 = 2D 300px). 얼굴은 2D 그리기 코드를 Canvas 2D로 옮겨 몸 텍스처(2048) 위에 그린다. 표정 전환·깜빡임·시선은 캔버스를 다시 그려 텍스처를 갱신한다.
- **리그:** 단순한 몸은 관절 = Group 계층이 빠르고 안정적이다(SkinnedMesh 불필요). `pose({x, z, turn, up, armL/armR, legs…})`, `setFace(mood)`, `hold(prop)`, `prop('bottle'|'mop')`.
- **새 표정이 필요하면 새로 만든다.** "안쓰럽게"를 기존 `worry`로 했더니 찡그림으로 읽혀 거부됨 → 눈썹 안쪽이 올라가는 `pity`를 따로 만듦.
- **소품은 손에 쥔 방향을 앞으로.** 옆으로 0.3 m 삐져나온 휴가권이 충돌을 만들었다.

## 3. 움직임
- **경로 `path()`:** 웨이포인트마다 서고 방향을 툭 꺾으면 점프컷처럼 튄다(사용자 지적). 길이가 0인 구간에서만 끊어 "다리(leg)"로 나누고, 다리 안에서는 사다리꼴 속도(시작·끝만 가감속), 방향은 0.3 m 앞을 내다본 값으로.
- **방향 전환은 lerp로 섞는다:** 도착 방향 → 바라볼 방향 → 떠날 방향을 `smooth(t0, t1)`로.
- **문 통과:** 캐릭터가 문틀보다 넓으면 통과 순간은 컷으로 넘긴다. 문은 안쪽으로 크게(90° 넘게) 열고, 문 뒤 인물은 문이 열린 뒤에만 보이게.
- **좁은 곳:** 팔을 몸에 붙이고(tuck) 지나간다. 상자·기계는 돌아가는 길을 만든다.

## 4. 공간·조명(애니매틱)
- 공간마다 고유 색과 그 기관의 일을 하는 기계를 둔다. 안에서 빛나는 재료와 빛 번짐, 공중에 뜬 원형 무대 너머 끝없는 바깥 세계.
- 컷 정의 `{ dur, set, cast, apply(t, ctx) → { cam:{pos,target,fov}, key, hemi, env, bloom } }`. 평상시 밝기는 key≈0.85~1, hemi≈0.32~0.45, env≈0.28~0.4. 정전·빛이 빠지는 장면은 이 값을 낮춘다.
- 톤매핑은 NeutralToneMapping(Blender의 Khronos PBR Neutral과 같음). 블룸 UnrealBloom(문턱 0.92).
- 꺼진 조명은 `visible=false`로(그림자 비용이 빠짐).
- 버그 기억: TorusGeometry 난간은 `rotation.x = +π/2`(부호를 틀리면 모든 세트에서 거울상이 됨).

## 5. 렌더·검사 도구(`render_film.mjs`, headless Chrome + SwiftShader)
- `still`(정지) · `check`(충돌) · `cuts`(컷별 프레임 + mp4 + collide.txt) · `frames`(일부 프레임만 다시) · `eval`(아무 값 확인) · `probe` · `audit` · `export`.
- `NORENDER=1`이면 그리지 않고 상태만 계산 → 전 컷 충돌 검사를 빠르게.
- `eval` 출력은 `grep '^\['`로 읽는다(숫자 안에 "404"가 섞여 로그 필터에 걸린 적 있음).
- 이전 컷의 상태(망가진 펌프 등)가 필요한 컷은 PRE 프레임(`C9:4,C13:5.99`)을 먼저 돌린다.
- 로컬 서버(`python3 -m http.server 8124`)가 죽으면 모든 명령이 실패한다 — 먼저 확인.

## 6. Blender로 옮기기
### 6-1. 내보내기 전 자동 점검(`audit`) → 보완 표
| glTF로 안 넘어가는 것 | 보완 |
|---|---|
| Sprite(꿈 방울·해 후광) | 카메라를 향해 도는 평면(MeshBasic, 같은 그림) + 투명도 키 |
| InstancedMesh(흐르는 혈구·먼지·미생물; 그대로면 마지막 프레임에 멈춤) | 인스턴스마다 따로 움직이는 물체. 렌즈 1 m 안의 작은 것은 그 프레임만 숨김 |
| 꼭짓점 변형(숨 쉬는 커튼) | 프레임별 형태의 주성분 → 모프 타깃(가중치 0~1로 정규화, 최대 6개) |
| CanvasTexture(심전도·모니터·화이트보드) | 중복 제거 PNG 시퀀스 + Blender `image_user.frame_offset` 키(CONSTANT). 작은 배경 화면은 초당 12장 |
| texture.offset 흐름(벨트·바다) | 매핑 노드 Location 키(`(ox, 1-oy-ry)`) |
| PointLight 세기 변화(glTF엔 고정값만, 그것도 거의 0으로 들어옴) | 프레임별 세기·색 키, three cd × 30 W |
| 노출·조명 키 | 노출이 아니라 조명 세기로(아래) |
| 항상 투명한 메시 | 뺀다 |
점검기가 놓친 적 있는 것: InstancedMesh(처음엔 항목이 없어 "차이 없음"이라고 잘못 보고함), 톤매핑 차이, 한쪽 면 재질, 초점. 새 작품에선 이 넷을 먼저 확인한다.

### 6-2. Blender 장면(`heart_pixar.py`)에서 검증된 값
- **색: Khronos PBR Neutral**, 노출 −0.25 고정. AgX Punchy는 금빛 기둥·바다를 회색으로 바래게 해서 사용자가 Neutral을 골랐다.
- **밝기 변화는 조명 세기로:** `dimf = clamp(lum/0.9)`, `lum = 0.5·key + 0.3·hemi/0.4 + 0.2·env/0.35`. 키·필·림·바닥반사·월드에 모두 곱한다. 노출 키로 하면 하늘·화면·전구 같은 발광체까지 어두워져 틀린다.
- 조명: 원판 면광원 키 260 W·필 70·림 450·바닥반사 45, 카메라·주인공을 따라 프레임마다 위치 키. 카메라에는 안 보이게(`visible_camera=False`). 점조명도 마찬가지(렌즈 앞에서 큰 얼룩이 됨).
- 캐릭터 재질: 속살 산란 0.2(반경 1, .45, .3, 크기 .06), 코트 0.12, 윤기 0.08. 발광 재료 ×2.5, 재질 애니메이션 발광 ×3.
- **초점:** 주인공이 화면 안에 있고 가려지지 않으면 주인공까지, 아니면 화면 가운데 레이캐스트 거리(인서트 컷이 통째로 흐려지던 것 해결). f/2.8, 바깥 원경 세트는 f/4.
- **한쪽 면 재질의 뒷면은 카메라 광선에서만 투명**(Backfacing × Is Camera Ray → Transparent 섞기). three는 벽 밖 카메라가 방 안을 보는데 Blender는 양면을 다 그려 화면이 검게 막혔다.
- 안개: 미스트 패스, 애니매틱과 같은 near~far, 바깥 60%·실내 15%(실내를 짙게 하면 뿌옇게 바램). 바깥은 바다 원판 끝을 감추는 데 필요.
- 빛 번짐: 글레어 Bloom 문턱 0.85, 세기 0.6×bloom/0.5 키.
- **모션 블러 정리(필수):** ① 순간이동(입자가 파이프 끝에서 처음으로) ② 사원수 부호 뒤집힘 ③ 보이기 전환(크기 1e-4↔1) ④ 컷 안 카메라 전환 — 모두 두 프레임 사이 한가운데(f−0.5)에 새 값 키를 넣고 앞 키를 CONSTANT로. 카메라 전환 판정은 **이웃 프레임보다 4배 이상 튀는 변화만**(위치 0.05 m·회전 2°·화각 1° 이상). 단순 임계값(중앙값×8)은 서서히 빨라지는 달리 이동을 전환으로 잡아 화면 전체가 소용돌이치듯 번졌다.
- 렌더: Cycles OptiX, 적응형 + 디노이즈, 96샘플 1280×720. RTX 3070 단독이 3070+1050보다 빠름(3프레임 82초 대 98초). 프레임당 6~9초.
- 일부만 다시: `--frames A-B`(1부터) 또는 `--framelist 143,144`(애니매틱 프레임 번호).

### 6-3. Blender 5.3 API 함정
- `use_nodes`는 믿지 말고 `m.node_tree`로 확인.
- 액션이 슬롯 방식: glTF 임포트는 **한 액션을 여러 물체가 나눠 쓴다** → `strip.channelbag(ad.action_slot)`로 물체별 F-커브를 얻는다. `act.fcurves` 전체를 물체 하나의 것으로 보면 아무것도 못 고친다.
- `keyframe_points.insert()` 뒤에는 키 배열이 다시 잡혀 **앞서 얻은 키 참조가 무효**가 된다 → 삽입 뒤 다시 찾아서 고친다(화각·초점 키가 안 끊겨 전환 직전 프레임에 다음 화면이 겹쳤던 원인).
- 이미지 시퀀스 `frame_duration`이 짧으면 offset 적용 전에 잘려 0번만 보인다 → 길게(≥ F0+N+5).
- 얼굴·화면 PNG는 glTF UV에 맞게 위아래를 뒤집어 저장한다.
- 컴포지터 `scene.compositing_node_group`, 글레어 종류는 입력 `'Type'`, 영상 출력 `image_settings.media_type='VIDEO'`, 시퀀서 `se.strips`.
- glTF unlit 재질에는 Principled가 없다 → 투명도 키는 Transparent BSDF와 Mix로.

## 7. 사용자 PC에서 렌더(원격)
- 클라우드 서버(GPU 없음, CPU 2코어)는 같은 프레임에 약 13.5분 → PC 3070보다 약 100배 느리다(실측). 최종 렌더는 사용자 PC에서.
- 파일 전달: 작은 파일은 `device_commit_files`(stagedPath). 수백 MB 압축은 SendUserFile로 올린 뒤 fileUuid로 커밋(400 MB 이하). 결과는 `device_stage_files`로 가져온다.
- **감시기 `run_pc.py`:** PC의 Blender GUI 파이썬 콘솔에서 실행하면 `queue/*.json`을 이름 순서대로 처리한다(`unzip`/`render`/`encode`). 이름 접두어(q→r→s→t→u→v)로 순서를 정하고, 보류할 작업은 빈 작업(`"steps": []`)으로 덮어쓴다.
- GUI 창이 꺼지면 감시기만 멈추고, 이미 띄운 `blender -b`는 계속 돈다. 다시 켤 때는 남은 백그라운드 Blender가 끝날 때까지 기다린다. 로그 파일 수정 시각은 Windows에서 열린 채로는 안 바뀌어 믿을 수 없으므로 프로세스 명령줄로 확인한다.
- computer use 함정: `open_application`은 부를 때마다 새 Blender를 띄움(4개 열린 적 있음) → 이미 있으면 작업 표시줄 클릭(파일 탐색기 클릭 권한 필요). 키 입력은 마우스 아래 영역으로 감 → 콘솔 위에 마우스를 두고 입력. 끝나면 잠금 해제.
- 진행 확인은 예약 알림(send_later)으로 60~90분마다. 확인할 때는 상태·실패 단계·새 mp4 한 프레임을 본다.

## 8. 렌더 뒤 점검(필수, 합본 전에)
1. `qa/sharp_frames.py` — 프레임별 선명도가 이웃 중앙값의 35% 미만인 프레임(카메라 전환 잔상, 순간이동 줄, 렌즈 앞 얼룩).
2. `qa/black_frames.py` — 검은·평평한 프레임(벽 뒷면에 막힘).
3. 컷마다 6개 시점을 애니매틱과 썸네일로 나란히 → 상관이 낮은 순으로 눈 확인(검은 장면, 밝기·색 차이).
4. 걸린 프레임은 애니매틱과 비교해 원본 탓인지 확인한다(애니매틱 자체의 1프레임 결함도 그대로 옮겨진다).
5. 고친 뒤 해당 프레임만 `--framelist`로 다시 그리고 다시 인코딩 → 다시 점검 → 합본 → 컷 경계 앞뒤 프레임 시트 확인.

## 9. 남은 과제(다음 작품에서 풀 것)
- 카메라 기준 주인공 조명 때문에 어두워지는 장면에서도 주인공이 애니매틱보다 밝다. 조명 감쇠를 세게 해도 차이가 작았다 → 장면 조명(애니매틱의 key·hemi·env 방향·세기)을 그대로 옮기고 주인공 조명은 보조로만 쓰는 구성을 처음부터 시험할 것.
- three.js 점조명의 `distance` 범위 컷오프는 Cycles에 없다 → 넓게 새는 빛을 감안해 세기를 정할 것.
