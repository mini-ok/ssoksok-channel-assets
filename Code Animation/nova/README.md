# nova — 허상공방 지식 쇼츠 2기 (규모 체감 모션그래픽)

다른 Claude 계정·새 세션이 이 폴더만 보고 같은 방식으로 쇼츠를 이어 만들 수 있게 정리한 문서다.
1기(같은 화풍의 규모 체감 쇼츠)는 `../scale/`, 종이 지식 쇼츠는 `../trivia/`, 채널 운영 규칙은 `../_channel/`.

- 형식: 세로 1080×1920, 30fps, **30~70초**(예: 본편 약 24초 + 마무리 문장 약 14초 + 끝 화면 7초 = 45초), 대사 없음, 영·한 자막.
- 2026-11-28 기준 46편(`ep_*.py`). 영상(mp4)은 저장소에 넣지 않는다(코드로 다시 만든다). 사용자 PC 사본: `K:\AI\AI자동화애니메이션테스트\shorts\nova\`.

## 1. 지키는 규칙 (사용자 지시, 2026-11-28 고침 = 규칙 2판)
1. **화면 디자인**: 이야기·소재에 가장 어울리는 화풍을 고른다. 이미 쓴 화풍은 되도록 피하되(4장 목록), **그 이야기에 가장 맞으면 다시 써도 된다.**
2. **소리**: 악기·소리는 **겹쳐 써도 된다.** 이야기와 화면 디자인에 가장 알맞은 것을 고른다.
3. **길이**: **30초 이상 1분 10초 이하.** (`rules=2`면 `finalize`가 범위를 벗어난 길이를 막는다.)
4. **마무리 문장(coda)의 여운을 길게**: 불교·기독교·철학의 울림이 있는 짧은 3줄(영·한). 줄 사이 2.8초, 마지막 줄 뒤 5.6초 머문다(`STEP2`, `HOLD2`). 편마다 다르게, 앞 편과 같은 말 반복 금지. 소리도 줄마다 음을 길게 끌어 준다.
5. **끝 화면(허상공방 인장이 나오는 곳)에서 구독·좋아요를 감성적으로 권한다.** 끝 화면 디자인 안에서, 그 편의 이야기와 이어지는 한 문장(`cta=(영어, 한글)`) + '좋아요'·'구독' 칸이 차례로 채워진다. 명령조("구독 눌러 주세요")가 아니라 이야기의 뒷말처럼 쓴다. 예: 〈한 달마다 새 피부〉 → "내일 새로워진 당신을, 다음 이야기로 기다릴게요".
6. **아래쪽 글자는 적게, 그러나 균형이 먼저.** 폰에서는 채널명·제목이 아래를, 좋아요·댓글 버튼이 오른쪽 아래를 가린다. 그래서 본편의 숫자·라벨·"계산" 표시 같은 **꼭 읽혀야 하는 글자는 y 1450 위**(1080×1920 기준)에 두고, 맨 아래 띠에는 글자를 두지 않는다. 다만 **화면 균형을 깨면서까지 위로 몰지는 않는다**(사용자 지시 2026-11-28: 글자를 위로 몰았더니 균형이 나빠 되돌림).
   - 마무리 3줄은 **1판 배치 그대로**(화면 가운데, 폭 960). 시간만 길어졌다.
   - 끝 화면은 가운데에 균형 있게(위 510 ~ 아래 1510). **구독·좋아요 칸은 가려지는 영역에 조금 걸쳐도 된다.**
   - 본편은 자막 카드 위쪽(y 176~510), 숫자·라벨은 카드 바로 아래 띠(y 530~700), 그림은 그 아래.
   - 공개된 안전 영역 수치는 자료마다 다르다(아래 300~670px, 오른쪽 100~190px). 엄격한 규칙이 아니라 참고 기준으로 쓴다.
7. **주제**: 규모가 체감되고, 궁금증을 일으키고, 살면서 쓸모 있는 것. 이미 다룬 주제 반복 금지(5장). 금성·물속 소리는 쓰지 않는다.
8. **사실은 웹으로 확인**하고 출처를 끝 화면(`sources`)과 설명란에 쓴다. 직접 계산한 값은 화면과 출처에 "calculated / 계산"이라고 밝힌다. 가정(보폭 0.75m, 종이 0.1mm 등)도 출처 줄에 적는다. 자료마다 수치가 다르면 더 믿을 만한 출처를 고르고 그 사실을 사용자에게 알린다.
9. **자막은 영·한 비슷한 크기**(영어 위, 한글 아래). 강조어는 `*별표*`로 감싸면 색이 바뀐다.
10. **길이를 채우려고 같은 장면을 반복하지 않는다.**
11. 공개 저장소이므로 사용자 고유 작법 용어를 쓰지 않는다. 비밀값(토큰·키)은 파일·대화에 넣지 않는다.

2026-11-26까지 만든 45편은 옛 규칙(약 32초, 화풍·소리 겹침 금지, 끝 화면에 권유 없음)으로 만들었다. 새 편은 모두 `rules=2`로 만든다. 기준 구현: `ep_skin.py`.

## 2. 한 편 만드는 순서
1. 주제 고르기 → 사실 2~4개를 웹에서 확인(출처 기록).
2. 화풍·소리 고르기(이야기에 가장 맞는 것. 4장 목록 참고).
3. `ep_<이름>.py` 작성(3장 틀, `rules=2`). 장면은 보통 4개(약 5~6초씩) + coda + 끝 화면. 첫 장면부터 화면에 움직임이 있어야 한다(검수 보고에 "정지 구간"이 길게 나오면 도입이 약한 것).
4. **정지 화면 확인**: `MG_SAFE=1 python3 ep_<이름>.py still /tmp/x.png 2 7 12 18 30 40` → 실제 크기(또는 절반)로 직접 열어 본다. `MG_SAFE=1`은 가려질 수 있는 영역을 **붉게 칠해 보여 주는 점검용 표시**다(실제 영상에는 안 나온다. 사용자가 디자인의 일부로 오해한 적이 있으니, 사용자에게 보이는 그림은 이 표시를 끄고 뽑는다). 꼭 읽혀야 하는 글자가 붉은 영역에 묻히지 않는지, 화면 균형, 글자 겹침, t=0 오류를 본다.
5. 렌더: `./make.sh <이름>` 또는 대기열(`echo "nova <이름>" >> $NOVA_WORK/queue.txt`, `tools/queue.sh`는 하나만).
6. 검수 보고 읽기: `$NOVA_WORK/qa_<이름>/report.md`와 `sheet_00.jpg`. P0가 있으면 고치고 다시 렌더.
7. 사용자에게 보내기 → 사용자 PC에 저장 → 확인받은 뒤 `tools/outbox_nova.py`로 업로드 대기열(shorts-outbox)에 넣기.

렌더는 45초 한 편에 약 5~6분(2코어). 무거운 후처리(median blur, 큰 가우시안)를 프레임마다 하면 느려진다.

## 3. 코드 틀
`base.py`가 화면 크기, 카드, coda, 끝 화면, CLI를 맡는다. 편 파일은 그림(`draw`)과 소리(`sound`)만 직접 만든다.

```python
from base import *          # DW, DH(1080x1920), W, H(배율 적용), SC, ramp, smooth, txt, surf, arr, over, BLK, BOLD, SERIF ...
import sfx as S

def draw(t):                # 시각 t의 순수 함수. BGR float(H, W, 3) 0..1 을 돌려준다
    s, cr = surf()          # cairo 투명 판(좌표는 1080x1920 기준)
    ...                     # 장면별로 a = ramp(...) * (1 - ramp(...)) 로 들어오고 나간다
    return over(BG, s)      # 또는 np.ascontiguousarray(arr(s)[..., :3])

def sound(path):
    m = S.Mix(EP['DUR'], seed); tc = EP['t_coda']
    m.put('mus', t, S.piano(f, dur, g)); m.put('fx', t, S.bell(...)); m.put('amb', 0, S.drone(...))
    m.write(path, rev_mus=2.4, wet_mus=0.4)

EP = finalize(dict(rules=2, t_coda=23.6, draw=draw, sound=sound, end_icon='star', grain=0.0,
    title_en_card='...', title_ko_card='...', pal=dict(hi=..., endbg=...),
    card_style=dict(box='paper', bg=..., ink=..., hi=..., y=180, fe=BOLD, fk=BLK),
    cards=[(0.3, 4.0, ['영어 1줄', '*강조* 2줄'], ['한글 1줄', '*강조* 2줄']), ...],
    coda=[('en', 'ko'), ('en', 'ko'), ('en', 'ko')],
    coda_style=dict(dim=0.5, blur=8, tint=..., ink=..., hi=..., fe=BOLD),
    cta=('이야기와 이어지는 영어 한 문장', '감성적인 한글 권유 한 문장'),   # 끝 화면 구독·좋아요 권유
    sources=['출처 1', '출처 2 (calculated 표시)'],
    yt=dict(title_en='... #Shorts', title_ko='...')))

if __name__ == '__main__': main(EP)
```

`rules=2`가 하는 일(`base.py`): 여운 간격(`STEP2` 2.8초, `HOLD2` 5.6초, 편마다 `coda_step`·`coda_hold`로 조정), 끝 화면 7초(`end_card2`: 제목 → 인장 → 크레딧 → 출처 → 권유 문장 → '좋아요'(끝 화면 +3.2초)·'구독'(+4.0초) 칸이 채워짐. 소리에서 이 두 시각에 맑은 음을 하나씩 넣는다), 길이 30~70초 검사. 마무리 3줄의 배치는 1판과 같다.

CLI: `info` / `still <png> t1 t2 ...` / `one <png> t` / `frames <dir> k0 k1` / `sound <wav>`.
`make.sh <이름>`: 프레임(2프로세스) → 인코딩 → 소리 → `_kit/vfx.loud`(−14 LUFS) → `_kit/vfx.qa report` → 정리.

`sfx.py` 악기: piano, upright, organ, harpsichord, celesta, kalimba, pizz, pluck, koto, shakuhachi, ney, lute, gurdy, dulcimer, bowed, glassharp, theremin, steeldrum, handpan, musicbox, fm, taiko, kick, hihat, brush, tok, bell, beep, tick, modem, static, thunder, rain, rainstick, stream, swoosh, icecrack, metaldrone, drill, drone, typekey, typebell, bird, woodflute, chalk, step 등. 서명은 `grep -n "^def " sfx.py`.

## 6. 업로드 대기열(shorts-outbox)과 PC 저장
- 공개 저장소의 `shorts-outbox` 브랜치에 `index.json`({items:[{slug,dir,created}], per_run:2})과 `shorts/<slug>/video.mp4`·`meta.json`이 쌓인다. 업로더(예약 실행)가 **한 번에 2편(per_run 2)**씩 올린다. 업로드 쪽 안내: `../trivia/` 의 handoff 문서와 `../_channel/shorts_playbook.md`.
- 넣기: `tools/outbox_nova.py`의 META에 한 줄 추가(slug, ep, 영어 제목, 한글 제목, 영어 설명(출처 포함), 한글 설명, 태그) → `cd /tmp && NOVA_OUT=<mp4 폴더> python3 <경로>/tools/outbox_nova.py <slug> ...`. 영어 제목·설명에는 한글을 넣지 않는다. 제목 100자 이하.
- 이 스크립트는 `/tmp`에 outbox를 clone한다. 쌓이면 디스크가 찬다 — 쓸 때마다 `/tmp/tmp*`(index.json이 든 clone) 정리.
- 옛 1기 편을 새 화풍으로 다시 만들었을 때는 `tools/outbox_remake.py`(slug 뒤에 `_v2`).
- 사용자 PC 저장: 세션이 PC와 연결돼 있으면 보낸 파일을 `device_commit_files`로 `K:\AI\AI자동화애니메이션테스트\shorts\nova\<이름>.mp4`에 쓴다(한 번에 1024MB·50개 이하).

## 7. 겪은 함정
- `make.sh`는 `out/<이름>.mp4`가 있으면 **건너뛴다(SKIP)**. 고쳐서 다시 렌더할 때는 먼저 옛 mp4를 옮기거나 지운다.
- `make.sh`의 `info`는 `MG_SCALE=0.25`로 모듈을 불러온다. 모듈을 불러올 때 계산하는 마스크·표본이 작은 해상도에서도 돌아가야 한다(예: `rng.choice`에 `min(len, n)`).
- t=0에서 cairo `scale(0)`이 나면 죽는다 → `max(s, 1e-3)`. 정지 확인 때 t=0을 꼭 넣는다.
- 알파를 무시하는 도형 함수(예: 불투명 fill)는 장면 경계·coda 배경에 남는다 → 모든 그리기에 장면 알파를 곱한다.
- 큰 글리프(⅓ 등)가 글꼴에 없으면 빈칸 → `1/3`처럼 ASCII로.
- 작은 크기의 `~`는 빼기표처럼 보인다 → `≈`.
- 글자가 카드 영역(위 176~510px)과 겹치지 않게, 꼭 읽혀야 하는 글자는 맨 아래 띠에 두지 않게(1장 6번). 마무리 문장 뒤로 앞 장면의 큰 숫자가 비치면 지저분하다 → coda가 시작될 때 장면 글자는 먼저 사라지게 한다.
- 검수 보고의 "끝 화면 밝기 튐", "정지 구간", "끝 무음"은 의도된 것. 필름 결처럼 일부러 넣은 깜박임은 P1로 나올 수 있다(사용자에게 알린다).
- 대화 세션의 백그라운드 프로세스는 턴이 끝나면 죽을 수 있다. 렌더를 기다릴 때는 턴 안에서 `sleep` 후 확인하고, `pgrep -af queue.sh`로 하나만 도는지 본다.
