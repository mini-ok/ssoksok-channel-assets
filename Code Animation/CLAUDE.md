# Code Animation 작업 규칙 (허상공방 — 다른 계정·새 세션도 이 규칙을 따른다)

처음이면 `README.md` → 작품 폴더 `README.md` → `_kit/README.md`(스킬 등록·환경 준비) 순서로 읽는다.

## 진행 방식 (사용자 지시)
- 시간이 드는 전체 렌더(1080p 컷 묶음, 인코딩) 전에 **정지 샘플 → 540p 짧은 움직임(+소리) → 컨펌 → 전체 렌더**.
  새 기법·새 연출을 처음 쓸 때는 반드시 작은 샘플로 먼저 확인받는다.
- 샘플은 **실제 전달 크기**로 직접 열어 확인한 뒤 보낸다. 컷 경계 앞뒤의 위치·크기·상태 연결을 반드시 본다.
- 해석이 둘로 갈리는 요청은 두 시안을 나란히 보여 주고 고르게 한다. 그 밖의 세부는 Claude가 최선으로 정한다.
- 길이를 채우려고 같은 장면을 반복하지 않는다.
- 커밋·푸시는 요청이 있을 때만, 작업 브랜치에서. `main` 병합은 사용자 확인 후.

## 비공개 유지
- 이 저장소는 **공개**다. 사용자 고유의 시나리오 작법(구조 이름·용어)은 저장소 파일에 쓰지 않는다
  (씬 리스트에는 장면 설명만). 작법이 담긴 문서는 claude.ai 프로젝트 문서나 계정 스킬에만 둔다.
- 서비스 계정·TTS 키 등 비밀값은 대화·파일에 붙이지 않는다(환경 비밀값 사용).

## 기술 메모
- 영상(mp4)과 `*/cache/`는 저장소에 넣지 않는다(코드로 다시 만든다).
- 상태가 있는 컷(유체·번짐 누적)은 한 프로세스에서 처음부터 순서대로 렌더. 8GB 메모리에서 무거운 렌더는 두 프로세스까지.
- 문자열 키 캐시는 코드를 바꿔도 옛 결과를 재사용한다 — 그림 로직을 고치면 관련 캐시를 지운다.
- 수묵 작품은 `_kit/skills/ink-wash-animation`, 셀 작품은 `_kit/skills/cel-anime-direction`, 3D 캐릭터 작품은 `_kit/skills/code-3d-character-animation` 스킬을 따른다.
- 애니매틱을 Blender 등 다른 도구로 넘길 때는 차이 점검 → 보완안 의논 → 보완해서 내보내기(저장소 루트 `CLAUDE.md`).
