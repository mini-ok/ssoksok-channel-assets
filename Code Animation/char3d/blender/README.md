# 〈심장의 휴가〉 → Blender(Cycles) 변환

애니매틱(three.js)의 컷을 Blender로 옮겨 픽사풍 조명·재질로 다시 렌더하는 도구. 2026-11-14 Blender 판 v1을 이 흐름으로 만들었다(20컷, 1280×720, RTX 3070에서 약 8시간).

## 0. 기본 규칙: 차이 점검 → 보완안 의논 → 보완해서 내보내기
glTF로 그대로 안 넘어가는 것이 있다. 내보내기 전에 컷마다 자동으로 점검하고, 차이마다 보완 방법을 사용자와 정한 뒤 내보낸다.
```bash
python3 -m http.server 8124 &
NORENDER=1 node render_film.mjs audit A1 C5 C6 …     # 컷마다 'AUDIT {json}' 한 줄
```
점검 항목: 스프라이트·선·점, 움직이는 인스턴스, 꼭짓점이 변하는 메시, 바뀌는 캔버스 텍스처, 무늬 이동(텍스처 offset), 점조명, 재질 visible 토글, 내보낼 수 없는 재질, 장면 밖 물체, 안개·배경 변화, 빛 번짐 변화.

## 1. 내보내기 (`char3d/`에서)
```bash
node render_film.mjs export <폴더> A1 C5 … C16      # PRE(기본 C9:4,C13:5.99)로 이전 컷 상태를 먼저 맞춤
```
컷마다
- `<컷>.glb` — 공간 + 출연진 + 카메라, 24fps로 구운 위치·회전·크기. 숨는 물건은 크기 1e-4.
- `<컷>.json` — 프레임 수, 화각·초점 거리(프레임별), 애니매틱 조명 값·빛 번짐, 안개(색·near·far), 얼굴/화면 번호, 점조명 세기·색, 무늬 이동, 모프 정보.
- `faces/` 얼굴 상태별 몸 텍스처(1024px, glTF UV에 맞게 위아래 뒤집음), `screens/` 화면 그림 시퀀스.

`export_scene.js`가 넣는 보완
| 애니매틱 | Blender로 |
|---|---|
| 스프라이트(꿈 방울·해 후광) | 카메라를 향해 도는 평면 + 투명도 키 |
| InstancedMesh(혈구·먼지·미생물) | 인스턴스마다 따로 움직이는 물체. 렌즈 1 m 안의 작은 것은 그 프레임만 숨김(심도 얼룩 방지) |
| 꼭짓점 변형(커튼) | 주성분 모프 타깃(0~1 가중치, 잔차 0.4% 이하까지 최대 6개) |
| 캔버스 화면(심전도·모니터·화이트보드) | 중복 제거 PNG 시퀀스. 128×96 이하 화면은 초당 12장, 나머지 24장 |
| 텍스처 offset 흐름(벨트·바다) | 매핑 노드 위치 키 |
| 점조명 | 프레임별 세기·색 |
| 초점 | 주인공이 화면 안·안 가려지면 주인공까지, 아니면 화면 가운데 물체까지 |
| 항상 투명(opacity 0) 메시 | 뺌 |

## 2. Blender 장면·렌더
```bash
blender -b -P blender/heart_pixar.py -- <폴더> C8 --res 1280x720 --samples 96 --render
```
옵션: `--frames A-B`(1부터) · `--framelist 143,144`(애니매틱 프레임 번호만 골라 다시 그리기) · `--view neutral|agx`(기본 neutral) · `--fog 0.6` · `--lightk 30` · `--fstop 2.8` · `--gpu 3070|all` · `--cpu` · `--out DIR`

하는 일
- 색: **Khronos PBR Neutral**(애니매틱의 NeutralToneMapping과 같음. AgX는 금빛·바다가 회색으로 바램), 노출 −0.25 고정.
- 조명: 원판 면광원 키·필·림·바닥반사가 카메라·주인공을 따라감. 장면 밝기 변화는 **조명 세기**로(`lum/0.9`). 노출로 하면 하늘·화면 같은 발광체까지 어두워짐. 점조명은 three 세기 × 30 W, 카메라에는 안 보이게.
- 재질: 캐릭터 속살 산란·코트·윤기. 발광 재료 ×2.5. 재질 애니메이션(발광·색·투명도) 키. glTF unlit 평면의 투명도는 Transparent 섞기로.
- 한쪽 면 재질(three 기본): 카메라 광선에서만 뒷면을 투명하게. 벽 밖 카메라가 방 안을 보는 애니매틱 구도용이고, 조명·그림자는 그대로.
- 모션 블러 정리: 순간이동(파이프 끝→처음), 사원수 부호 뒤집힘, 보이기 전환(크기 1e-4↔1), **컷 안 카메라 전환**(위치·회전·화각이 이웃 프레임보다 4배 이상 튀는 프레임만)은 두 프레임 사이 가운데에서 끊음.
- 안개: 미스트 패스로 애니매틱과 같은 near~far. 바깥 세트 60%, 실내 15%.
- 빛 번짐: 글레어 Bloom(문턱 0.85), 세기는 애니매틱 bloom 값을 따라 키.
- 렌더: Cycles OptiX, 적응형 + 디노이즈. 3070과 1050을 함께 쓰는 것보다 3070만 쓰는 쪽이 빠름(3프레임 82초 대 98초).

Blender 5.3 API 주의: `use_nodes`는 믿지 말고 `m.node_tree`로 확인. 액션은 슬롯 방식이라 한 액션을 여러 물체가 나눠 쓰므로 `strip.channelbag(ad.action_slot)`로 물체별 F-커브를 얻음. 키를 삽입하면 키 배열이 다시 잡혀 앞서 얻은 키 참조가 무효가 됨. 컴포지터는 `scene.compositing_node_group`, 영상 출력은 `image_settings.media_type='VIDEO'`, 시퀀서는 `se.strips`.

## 3. 사용자 PC에서 대기열로 렌더 (`run_pc.py`)
- PC의 Blender GUI 파이썬 콘솔에서 `import os; exec(open(r'<작업폴더>\run_pc.py', encoding='utf-8').read())`. `queue/*.json`을 이름 순서대로 처리한다(단계: `unzip` / `render` / `encode`). 상태는 `status.json`, `log.txt`, `last_<단계>.txt`에 남는다.
- GUI 창이 꺼지면 감시기가 멈춘다. 이미 띄운 백그라운드 렌더는 계속 돈다. 다시 켜면 남은 `blender -b` 프로세스가 끝날 때까지 기다린 뒤 다음 작업을 잡는다.
- 끝나면 `encode_seq.py`로 컷 mp4를 만들고, 서버에서 `./assemble_blender.sh <mp4 폴더>`로 타이틀·소리를 합친다.

## 4. 렌더 뒤 점검 (`qa/`)
```bash
python3 qa/sharp_frames.py *.mp4    # 통째로 번진 프레임(카메라 전환 잔상, 순간이동 줄 등)
python3 qa/black_frames.py *.mp4    # 검은·평평한 프레임(벽 뒷면에 막힘 등)
```
- 애니매틱 같은 시점과 썸네일을 나란히 놓고 비교해, 크게 다른 컷은 눈으로 확인한다.
- 문제 구간은 `--framelist`로 그 프레임만 다시 그리고 다시 인코딩한다.

## 남은 차이
- 어두워지는 장면(C10·C11a·C11e)에서 주인공이 애니매틱보다 밝음. 카메라 기준 주인공 조명 때문이고, 맞추려면 조명 구성을 다시 짜야 한다.
- 바다 장면은 애니매틱보다 살짝 파스텔조.
