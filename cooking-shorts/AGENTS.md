# 건강요리 숏츠 작업 필수 지침

이 폴더 작업 전에 `CLAUDE.md`, `SERIES_BIBLE.md`, `MENU_HISTORY.md`를 읽는다.

핵심은 **장기 요리사가 자기 장기에 도움 되는 요리를 만들고, 조리 후 여성 나레이션이 이유와 근거를 설명하는 구조**다. 일반적인 영양가만으로 캐릭터를 배정하지 않는다. 메뉴부터 만든 뒤 장기와 효능을 끼워 맞추지 않는다.

건강 포인트 → 신뢰할 수 있는 근거와 적용 조건 → 주재료·레시피 → 해당 장기 쉐프 순서로 기획한다. 제작 전 `EPISODE_PLAN_TEMPLATE.json`을 복사해 기획서를 채운다. 렌더 전 설명 대사, 출처 화면, 순서와 조건을 확인한다. 자동 점검은 구조 누락을 찾는 용도이며 근거의 의학적 타당성을 대신하지 않는다.

상세 규칙과 필수 검수 항목은 `SERIES_BIBLE.md`를 따른다. 같은 주재료·비슷한 요리 스타일은 최소 10편을 사이에 둔 뒤 다시 사용한다. 부재료·양념은 재사용 가능하다.

가능하면 장기별로 돌아가며 출연한다. 3편은 심장 확정이며 이후 다른 장기를 우선 검토한다. 장기 순환을 맞추려고 건강 근거를 끼워 맞추지 않는다.

항상 해외에서도 쉽게 구할 수 있는 재료와 기본 조리도구로 만드는 간단 요리를 선정한다(사용자 재확인 2026-10-29). 특정 국가의 전용 소스·제품에 의존하지 않는다. 냉동·통조림 등 접근성 좋은 대체재가 있으면 기획서에 적는다.

## 건강근거 수치 박스 필수 (사용자 지시 2026-10-31)

앞으로 모든 대본의 조리 후 건강근거 장면에는 **해당 레시피 분량의 핵심 영양소 함량을 큰 텍스트 박스로 표시**한다. 여성 설명 나레이션은 유지하되 숫자를 대사에 억지로 넣지 않는다.

- 공인 식품성분표·공공기관 자료 또는 실제 제품 영양표시를 사용하고, 출처 URL·확인일·원자료 단위·계산식을 기획서에 기록한다.
- 전체 레시피와 1인분/1회 섭취량을 구분하고, 생재료/조리 후 중량 및 식품 종류·제품 조건을 맞춘다. 투입 재료의 계산값을 완성품 실측값처럼 쓰지 않는다.
- 일일 권장량 대비 비율은 기준 국가·연령·성별·권장량을 명시한다. 영양표시 DV와 개인 권장섭취량을 혼용하지 않는다. DHA처럼 단독 권장량이 미설정이면 함량과 미설정 사실만 표시하고 백분율을 만들지 않는다.
- 수치는 적절히 반올림해 ‘약’으로 표시하고 제품·어종·조리별 차이를 읽을 수 있는 크기로 안내한다. 숫자로 치료·예방 효과가 보장되는 인상을 주지 않는다.
- 함량·단위·백분율·섭취분량·출처를 검산하고, 실제 영상에서 박스가 겹치지 않고 충분히 읽히는지 검수한다. 정보가 많으면 두 화면으로 나눈다.

## 다운로드 ZIP은 에피소드별로만 제공 (사용자 지시 2026-11-02)

앞으로 여러 에피소드를 합친 통합 ZIP을 만들거나 기본 다운로드로 안내하지 않는다. **에피소드마다 한글·영문 영상과 업로드 자료를 함께 담은 개별 ZIP 하나**를 만들고, 최종 답변에는 각 에피소드 ZIP의 직접 다운로드 링크를 제공한다. 기존 통합 ZIP은 이 지시만으로 삭제하지 않는다.

## 클라우드 직접 저장이 최신 기본값 (2026-11-04)

사용자는 PC가 꺼져 있어도 매일 새 요리 두 에피소드를 한·영(총 네 영상)으로 제작해 GitHub에 저장하도록 요청했다. 웹 ChatGPT Work의 구독 클라우드 예약을 쓰고, 렌더링은 .github/workflows/cooking-cloud.yml, 원본 영상·업로드 자산 보관은 에피소드별 GitHub Release를 사용한다. cloud/README.md와 cloud/WEB_SCHEDULE_PROMPT.md를 따른다. **로컬 PC에 새 영상·음성을 만들거나 ZIP을 생성하지 않는다.** 예전 개별 ZIP 규칙은 사용자가 수동 다운로드 묶음을 따로 요청할 때만 적용한다. 별도 OpenAI API 키나 유료 대형 runner로 자동 전환하지 않는다. 유튜브 업로드는 별도 작업이다. 예약·클라우드 제작의 실제 성공을 확인하기 전 완료라고 말하지 않는다.
